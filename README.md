# RSS → DeepSeek → Telegram

Лёгкий бот: читает RSS/Atom-ленты, прогоняет каждую новость через DeepSeek по вашему
шаблону и публикует результат в Telegram-канал. Управление — командами в личке с ботом
(конфигурационные файлы после установки трогать не нужно) либо, по желанию, веб-панелью
в браузере — та же логика, тот же процесс.

Зависимости: `aiogram` + `feedparser`. Хранилище — SQLite в одном файле. Ни базы данных,
ни брокера; в простое бот спит и ресурсов не потребляет. Веб-панель — опция, по
умолчанию выключена (см. ниже).

📦 **[INSTALL.md](INSTALL.md)** — установка на Ubuntu 24.04, обновление, диагностика
⚙️ **[SETUP.md](SETUP.md)** — настройка лент, шаблонов, режим отладки, лимиты и деньги

## Возможности

* **Ленты** — добавление и удаление на ходу, проверка адреса при добавлении,
  индивидуальный шаблон для отдельной ленты, ошибка одной ленты не мешает остальным.
* **Сайты без RSS** — `/addsite <url>`: новые статьи находятся через веб-поиск
  (Serper.dev), а не разбором ленты — у многих сайтов
  собственные средства узнать «что нового» (sitemap.xml, страница списка
  новостей) отдают устаревший из-за CDN-кэша снимок, поиск от этого не
  зависит. Заголовок, описание и картинку бот дочитывает со страницы самой
  статьи, но только для тех записей, что уже прошли остальные фильтры.
  Нужен бесплатный ключ API (см. SETUP.md). Управление такое же, как у
  обычных лент — отдельный раздел «Сайты без RSS» на «Лентах».
* **Обработка через ИИ** — промпт целиком ваш, с плейсхолдерами новости. Любой
  OpenAI-совместимый провайдер: OpenRouter по умолчанию, DeepSeek напрямую, что угодно ещё.
* **Формат поста** — отдельно от промпта, с HTML-разметкой Telegram и проверкой
  корректности при сохранении.
* **Картинки из новости** — берутся из ленты и прикладываются сами: короткий пост
  уходит фото с подписью, длинный — с картинкой в превью над текстом.
* **Несколько картинок альбомом** — `/feedimages <id> on`: настройка отдельной
  ленты, не общая. Вместо одной бот скачивает до `/set max_images N` (1-10)
  картинок из тела статьи и публикует альбомом. Работает при любом режиме —
  обычном, Claude, Gemini.
* **Дубли между лентами** — новость, похожая на уже опубликованную с другой
  ленты (то же событие, другими словами), сама в канал не уходит — ждёт
  разбора на «Лентах» в веб-панели: посмотреть, опубликовать вручную или
  удалить. Настраивается и выключается: `/set dedup_enabled 0`.
* **Дублирование в VK** — те же новости на стену сообщества, с картинкой:
  разметка снимается, ссылки разворачиваются в текст. Включается ключом
  сообщества в `.env`, на ходу — `/vk on` и `/vk off`.
* **Режим отладки** — посты приходят в личку вместо канала, одну новость можно
  прогонять сколько нужно, подбирая промпт. Новости при этом не расходуются.
* **Учёт лимита ИИ** — расход по суткам, предупреждения в личку на 70% и 90%,
  контроль остатка кредитов.
* **Надёжность** — новости не дублируются и не теряются при перезапусках, сбоях
  модели, недоступном канале и правках заголовков в источнике.
* **Режим Claude** — включается командой `/claude on`: обработка через платный
  Claude вместо LLM_* из `.env`.
* **Режим Gemini** — включается командой `/gemini on`: обработка через Gemini
  вместо LLM_* из `.env`, обычно бесплатно. Взаимоисключимо с Claude —
  включён может быть только один из двух.
* **Редактирование опубликованного** — `/posts` показывает последние посты,
  `/setpost` меняет текст вручную, `/regen` перегенерирует его через ИИ заново
  из исходной новости, без republish. У альбома можно убрать отдельную
  картинку (`/delimage <id> <номер>` или в веб-панели), не трогая остальные.
* **Веб-панель управления** — та же функциональность в браузере вместо команд:
  ленты, контент, настройки, посты. Включается паролем в `.env`
  (`WEB_PANEL_PASSWORD`), по умолчанию выключена. С доменом и HTTPS
  (`WEB_PANEL_PUBLIC_URL`) открывается прямо в Telegram — командой `/panel`
  и кнопкой меню бота, как настоящий Mini App, и для всех `ADMIN_IDS`
  входит сама, без пароля, по подписи Telegram. Подробности и варианты
  доступа — в [SETUP.md](SETUP.md#веб-панель-управления).

## Быстрый старт

```bash
sudo apt install -y python3 python3-venv git
git clone <репозиторий> /opt/rss-deepseek-bot && cd /opt/rss-deepseek-bot
./install.sh        # создаст .env и остановится
nano .env           # BOT_TOKEN, CHANNEL_ID, ADMIN_IDS, LLM_API_KEY
./install.sh        # поднимет systemd-сервис
```

Затем напишите боту `/help`. Пошагово, включая где взять токены —
[INSTALL.md](INSTALL.md).

## Устройство

```
bot/config.py     переменные окружения и .env, проверка значений на старте
bot/db.py         SQLite: ленты, настройки, отметки «прочитано», расход
bot/rss.py        загрузка и разбор лент, условный GET по ETag
bot/llm.py        клиент к модели (/chat/completions, ретраи, учёт токенов)
bot/quota.py      лимиты и предупреждения на 70/90% (только для LLM_*, не Claude)
bot/vk.py         клиент VK: стена сообщества, загрузка фото, HTML → текст
bot/claude.py     клиент к Claude (Messages API) — режим /claude on
bot/publisher.py  цикл: лента → новые записи → модель → канал (и VK)
bot/handlers.py   команды управления
bot/web.py        веб-панель (aiohttp) — та же логика, что и в handlers.py, в браузере
bot/main.py       точка входа
```

Каждые `interval` минут бот обходит активные ленты. Новизна записи определяется по
`guid` (а если его нет — по ссылке с заголовком), отметки лежат в таблице `seen`,
поэтому перезапуск не приводит к повторным публикациям, а правка заголовка
в источнике — к дублю. Если сервер ленты поддерживает `ETag`/`Last-Modified`, бот
получает `304` и не качает содержимое; кэш обходится, когда с прошлого раза остались
неопубликованные новости, иначе они спрятались бы до следующего обновления ленты.

Схема базы обновляется на месте: недостающие колонки добавляются при старте, так что
обновление кода не ломает существующий `data/bot.db`.

## Куда расширять

* **Другая модель или провайдер** — `LLM_BASE_URL` и `LLM_MODEL` в `.env`, код
  не меняется. Модель ещё и переключается командой `/setmodel`.
* **Несколько каналов** — добавьте колонку `channel_id` в таблицу `feeds`
  и прочитайте её в `Publisher._send`.
* **Как выбирается картинка** — `rss._image`: порядок источников и отсев
  счётчиков там же. Отправка — `Publisher._send`, выключатель — `/set images 0`.
* **Фильтры по ключевым словам** — естественное место в `Publisher._process_feed`,
  сразу после формирования списка `fresh`.
* **Свой шаблон на ленту** — колонка `template` в `feeds` уже поддерживается кодом,
  нужна только команда для неё.

## Обслуживание

```bash
journalctl -u rss-deepseek-bot -f        # логи
sudo systemctl restart rss-deepseek-bot  # перезапуск
```

Всё состояние — `data/bot.db` и `.env`; для резервной копии достаточно скопировать их.
