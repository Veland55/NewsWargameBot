# RSS → DeepSeek → Telegram

Лёгкий бот: читает RSS/Atom-ленты, прогоняет каждую новость через DeepSeek по вашему
шаблону и публикует результат в Telegram-канал. Управление — командами в личке с ботом,
конфигурационные файлы после установки трогать не нужно.

Зависимости: `aiogram` + `feedparser`. Хранилище — SQLite в одном файле. Ни базы данных,
ни брокера, ни веб-сервера; в простое бот спит и ресурсов не потребляет.

📦 **[INSTALL.md](INSTALL.md)** — установка на Ubuntu 24.04, обновление, диагностика
⚙️ **[SETUP.md](SETUP.md)** — настройка лент, шаблонов, режим отладки, лимиты и деньги

## Возможности

* **Ленты** — добавление и удаление на ходу, проверка адреса при добавлении,
  индивидуальный шаблон для отдельной ленты, ошибка одной ленты не мешает остальным.
* **Обработка через ИИ** — промпт целиком ваш, с плейсхолдерами новости. Любой
  OpenAI-совместимый провайдер: OpenRouter по умолчанию, DeepSeek напрямую, что угодно ещё.
* **Формат поста** — отдельно от промпта, с HTML-разметкой Telegram и проверкой
  корректности при сохранении.
* **Режим отладки** — посты приходят в личку вместо канала, одну новость можно
  прогонять сколько нужно, подбирая промпт. Новости при этом не расходуются.
* **Учёт лимита ИИ** — расход по суткам, предупреждения в личку на 70% и 90%,
  контроль остатка кредитов.
* **Надёжность** — новости не дублируются и не теряются при перезапусках, сбоях
  модели, недоступном канале и правках заголовков в источнике.

## Быстрый старт

```bash
sudo apt install -y python3 python3-venv git
git clone <репозиторий> /opt/rss-deepseek-bot && cd /opt/rss-deepseek-bot
./install.sh        # создаст .env и остановится
nano .env           # BOT_TOKEN, CHANNEL_ID, ADMIN_IDS, LLM_API_KEY
./install.sh        # поднимет systemd-сервис
```

Затем напишите боту `/help`. Пошагово, включая где взять токены —
[INSTALL.md](INSTALL.md).

## Устройство

```
bot/config.py     переменные окружения и .env, проверка значений на старте
bot/db.py         SQLite: ленты, настройки, отметки «прочитано», расход
bot/rss.py        загрузка и разбор лент, условный GET по ETag
bot/llm.py        клиент к модели (/chat/completions, ретраи, учёт токенов)
bot/quota.py      лимиты и предупреждения на 70/90%
bot/publisher.py  цикл: лента → новые записи → модель → канал
bot/handlers.py   команды управления
bot/main.py       точка входа
```

Каждые `interval` минут бот обходит активные ленты. Новизна записи определяется по
`guid` (а если его нет — по ссылке с заголовком), отметки лежат в таблице `seen`,
поэтому перезапуск не приводит к повторным публикациям, а правка заголовка
в источнике — к дублю. Если сервер ленты поддерживает `ETag`/`Last-Modified`, бот
получает `304` и не качает содержимое; кэш обходится, когда с прошлого раза остались
неопубликованные новости, иначе они спрятались бы до следующего обновления ленты.

Схема базы обновляется на месте: недостающие колонки добавляются при старте, так что
обновление кода не ломает существующий `data/bot.db`.

## Куда расширять

* **Другая модель или провайдер** — `LLM_BASE_URL` и `LLM_MODEL` в `.env`, код
  не меняется. Модель ещё и переключается командой `/setmodel`.
* **Несколько каналов** — добавьте колонку `channel_id` в таблицу `feeds`
  и прочитайте её в `Publisher._send`.
* **Картинки из ленты** — `enclosure` и `media:thumbnail` доступны в `rss.Entry`;
  отправка идёт через единственный метод `Publisher._send`, там же можно вызвать
  `send_photo` (лимит подписи — 1024 символа).
* **Фильтры по ключевым словам** — естественное место в `Publisher._process_feed`,
  сразу после формирования списка `fresh`.
* **Свой шаблон на ленту** — колонка `template` в `feeds` уже поддерживается кодом,
  нужна только команда для неё.

## Обслуживание

```bash
journalctl -u rss-deepseek-bot -f        # логи
sudo systemctl restart rss-deepseek-bot  # перезапуск
```

Всё состояние — `data/bot.db` и `.env`; для резервной копии достаточно скопировать их.
