# Настройка

Всё настраивается командами в личке с ботом — файлы после установки править не нужно.
Команды принимаются только от аккаунтов из `ADMIN_IDS`, остальным бот не отвечает.

Если бот ещё не установлен — сначала [INSTALL.md](INSTALL.md).

---

## Порядок первой настройки

Рекомендую именно такую последовательность: сначала посмотреть результат в личке
и только потом пускать в канал.

```
/debug on                          # посты будут приходить вам, не в канал
/add https://lenta.ru/rss/news     # первая лента
/checknow                          # получить пост в личку
/settemplate ...                   # поправить промпт, если результат не нравится
/checknow                          # та же новость по новому промпту
/debug off                         # публикуем в канал
```

Разбор каждого шага — ниже.

## Ленты

```
/add https://lenta.ru/rss/news
/add https://habr.com/ru/rss/best/daily/ Хабр
```

Второе слово и всё после него — необязательное название, оно попадает в `{source}`
и в подпись поста. Если не указать, бот возьмёт название из самой ленты.

При добавлении адрес сразу проверяется: бот скачивает ленту, считает записи
и показывает последнюю. Если лента недоступна или пустая — она не добавится,
и вы увидите причину.

| Команда | Что делает |
|---|---|
| `/list` | все ленты: статус, время последней проверки, число прочитанных, ошибки |
| `/del 1` | удалить ленту вместе с её архивом прочитанного |
| `/pause 1` | временно выключить одну ленту |
| `/resume 1` | включить обратно |
| `/test 1` | прогнать последнюю новость через шаблон и показать результат, ничего не публикуя |

Номер (`id`) берётся из `/list`.

**Где брать адреса лент.** Обычно `https://сайт/rss`, `/feed`, `/rss.xml`,
`/feed.xml`. У многих сайтов ссылка есть в подвале страницы. Поддерживаются
и RSS, и Atom. Проверить вручную: `curl -s https://сайт/rss | head -20` — должен
быть XML с `<item>` или `<entry>`.

**Сколько лент.** Ограничения нет, но помните про расход модели: каждая новость —
один запрос. Оценить и проконтролировать поможет `/usage`.

## Шаблон для модели

Это главная настройка — именно она определяет, как будут выглядеть новости.
Промпт целиком ваш; бот только подставляет в него данные новости.

Посмотреть текущий:

```
/template
```

Задать свой — одним сообщением, перенос строки в Telegram это **Shift+Enter**:

```
/settemplate Ты редактор новостного канала. Перепиши новость на русском.

Требования:
- 2 предложения, только факты из источника
- никаких оценок и воды
- в конце 2 хештега

Заголовок: {title}
Текст: {summary}
```

Доступные плейсхолдеры:

| Плейсхолдер | Что подставляется |
|---|---|
| `{title}` | заголовок новости |
| `{summary}` | текст новости из ленты (HTML вычищен) |
| `{link}` | ссылка на источник |
| `{source}` | название ленты |
| `{published}` | дата публикации |

Хотя бы один из `{title}` / `{summary}` обязателен — без них модель не получит
саму новость, и такой шаблон бот не сохранит.

Вернуть исходный: `/reset template`.

### Примеры промптов

**Сухая выжимка:**

```
/settemplate Перепиши новость в одно предложение, максимально сухо, только факт.

{title}. {summary}
```

**С разбором и мнением:**

```
/settemplate Ты аналитик. Дай пересказ новости в 3 предложениях, затем строку
«Почему это важно:» и одно предложение о значимости. Без markdown.

Заголовок: {title}
Источник: {source}
Текст: {summary}
```

**Перевод на русский** (для англоязычных лент):

```
/settemplate Переведи новость на русский язык и сократи до 3 предложений.
Имена и названия компаний оставь в оригинале.

{title}
{summary}
```

После любой правки проверяйте `/test <id>` — увидите результат, ничего не публикуя.

## Формат поста

Шаблон отвечает за текст от модели, формат — за вёрстку готового сообщения.

```
/format
```

По умолчанию:

```
<b>{title}</b>

{ai}

<a href="{link}">Читать в источнике</a> · <i>{source}</i>
```

Здесь `{ai}` — ответ модели, остальные плейсхолдеры те же. Поддерживаются
[HTML-теги Telegram](https://core.telegram.org/bots/api#html-style):
`<b>`, `<i>`, `<u>`, `<s>`, `<code>`, `<pre>`, `<a href>`, `<blockquote>`.

Примеры:

```
/setformat {ai}

<a href="{link}">{source}</a>
```

```
/setformat <b>{title}</b>
<blockquote>{ai}</blockquote>
<a href="{link}">Источник</a> · {published}
```

Разметка проверяется при сохранении: незакрытый тег или тег, которого Telegram
не знает, бот отклонит с объяснением. Это не придирка — Telegram отверг бы такой
пост целиком, и публикация встала бы.

Вернуть исходный: `/reset format`.

## Режим отладки

Чтобы настраивать шаблон, не засоряя канал:

```
/debug on
/checknow
```

Пост приходит вам в личку с пометкой «ОТЛАДКА» и выглядит ровно так, как выглядел
бы в канале. Правите `/settemplate` или `/setformat`, снова `/checknow` — и видите
**ту же самую новость**, обработанную по-новому. Так можно сравнивать варианты
промпта на одном материале.

Важные свойства режима:

* в канал не уходит ничего;
* новости не помечаются прочитанными — после `/debug off` они опубликуются как
  обычно, ничего не теряется;
* автоматический цикл в отладке молчит, иначе одни и те же посты приходили бы
  в личку каждые `interval` минут. Проверка только по `/checknow`;
* кэширование лент отключено, поэтому одну новость можно прогонять сколько нужно.

Если бот на паузе (`/stop`), отладка тоже ничего не покажет — сначала `/start`.

Разовый предпросмотр без включения режима — `/test <id>`.

## Канал и публикация

| Команда | Что делает |
|---|---|
| `/setchannel @my_channel` | сменить канал; бот сразу проверит, что видит его |
| `/stop` | пауза: ленты не проверяются, публикаций нет |
| `/start` | снять паузу |
| `/checknow` | проверить ленты немедленно, не дожидаясь интервала |
| `/status` | полное состояние: канал, модель, ленты, все параметры |

Бот должен быть администратором канала с правом «Публикация сообщений». Если права
нет, в логах появится `Forbidden`, а новости останутся непрочитанными и уйдут
в канал после того, как права дадите — ничего не потеряется.

## Модель и деньги

По умолчанию используется OpenRouter и модель `deepseek/deepseek-v4-flash`.

```
/model                                     # текущая модель и подсказки
/setmodel deepseek/deepseek-v3.2           # сменить
```

Новая модель сразу проверяется живым запросом. Если она не отвечает или слага
не существует, бот вернёт прежнюю — публикации не сломаются.

**Бесплатных версий DeepSeek на OpenRouter нет.** Платные стоят копейки — оценка
при ~1500 токенах промпта и ~250 ответа на новость:

| Модель | За 1000 новостей |
|---|---|
| `deepseek/deepseek-v4-flash` (по умолчанию) | ~22 ₽ |
| `deepseek/deepseek-v3.2` | ~40 ₽ |
| `deepseek/deepseek-chat` | ~52 ₽ |
| `deepseek/deepseek-v4-pro` | ~70 ₽ |

При 20 новостях в день на модели по умолчанию выходит около 13 ₽ в месяц.

Если нужен строго нулевой счёт — бесплатные модели есть, но не DeepSeek:

```
/setmodel google/gemma-4-31b-it:free
/setmodel nvidia/nemotron-3-super-120b-a12b:free
/setmodel openai/gpt-oss-20b:free
```

У них суточный лимит запросов и очереди при перегрузке. Актуальный список —
[openrouter.ai/models?max_price=0](https://openrouter.ai/models?max_price=0).

Сменить провайдера целиком (например, на DeepSeek напрямую) можно в `.env`:
`LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`. Подойдёт любой OpenAI-совместимый API.

## Лимиты ИИ и предупреждения

Бот считает свои запросы по суткам UTC и предупреждает в личку, когда израсходовано
70% и 90% лимита:

```
🟡 Израсходовано 70% суточного лимита запросов
Запросов сегодня: 35 из 50
Модель: google/gemma-4-31b-it:free
Лимит: бесплатный тариф OpenRouter
Обнулится через 9 ч 12 мин (00:00 UTC)
```

Повторно на том же пороге за те же сутки сообщение не приходит. Пороги меняются:

```
/set alert_thresholds 50,80,95      # свои пороги
/set alert_thresholds               # пусто — выключить предупреждения
```

Текущая картина в любой момент:

```
/usage
```

Отслеживаются две разные вещи:

* **Запросы в сутки.** Актуально для бесплатных моделей (`:free`): у них лимит
  50 запросов в сутки, если кредиты никогда не покупались, и 1000, если куплено
  10 и более. Какой применить, бот определяет сам по данным ключа. Если нужно
  задать вручную: `/set free_daily_limit 50`.
* **Кредиты.** Если на ключе OpenRouter выставлен лимит трат, бот следит
  за остатком и предупреждает на тех же порогах.

Счётчик запросов бот ведёт свой, потому что провайдер его не отдаёт. Если тем же
ключом пользуется что-то ещё, эти запросы бот не увидит.

**Когда лимит всё же исчерпан**, модель отвечает ошибкой 429. Что произойдёт,
зависит от настройки `on_llm_error`:

* `raw` (по умолчанию) — новость публикуется без обработки, с исходным текстом
  из ленты. Ничего не теряется, но пост будет «сырым»;
* `skip` — новость откладывается до следующего прохода. В канале не появится
  ничего лишнего, но и новости задержатся.

```
/set on_llm_error skip
```

## Все параметры

Смотреть текущие значения — `/status`. Менять — `/set <ключ> <значение>`.

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `interval` | 15 | минут между проверками лент (`/interval 30`) |
| `max_per_cycle` | 3 | максимум новостей из одной ленты за проход — защита от лавины |
| `post_delay` | 5 | пауза между публикациями, секунды |
| `backfill` | 1 | сколько новостей опубликовать при первом опросе новой ленты; остальная история помечается прочитанной |
| `on_llm_error` | raw | `raw` — публиковать без обработки, `skip` — отложить |
| `disable_preview` | 0 | `1` — отключить превью ссылок в постах |
| `keep_seen` | 500 | сколько отметок «прочитано» хранить на ленту |
| `alert_thresholds` | 70,90 | пороги предупреждений о расходе, в процентах |
| `free_daily_limit` | 0 | суточный лимит запросов; 0 — определять автоматически |

### Как подобрать интервал и лимиты

Расход = число новостей во всех лентах. Ленты проверяются каждые `interval` минут,
но за один проход из каждой берётся не больше `max_per_cycle`.

* **Спокойный канал, минимум денег:** `/interval 60` и `/set max_per_cycle 2`.
* **Оперативные новости:** `/interval 5`. Помните про лимит 20 запросов в минуту
  у бесплатных моделей — при `post_delay` в 5 секунд вы в него не упрётесь.
* **Много лент (10+):** держите `max_per_cycle` на 1–2, иначе первый проход
  после простоя выдаст в канал десятки постов подряд.

## Частые вопросы

**Бот молчит на команды.** Ваш id не в `ADMIN_IDS`. Проверьте `.env`, узнайте id
у [@userinfobot](https://t.me/userinfobot), перезапустите сервис. Посторонним бот
не отвечает намеренно.

**В канал ничего не публикуется.** По порядку: `/status` — не на паузе ли и не
включена ли отладка; есть ли активные ленты в `/list`; нет ли там ошибок;
`/checknow` — что ответит; `journalctl -u rss-deepseek-bot -n 50`.

**При добавлении ленты сразу прилетела одна новость.** Так и задумано: `backfill=1`.
Остальная история помечается прочитанной, чтобы канал не завалило. Отключить —
`/set backfill 0`.

**Новости приходят с большой задержкой.** Проверка идёт раз в `interval` минут,
плюс сам сайт может обновлять ленту с задержкой. Уменьшите `/interval`.

**Посты слишком длинные или обрезаются.** Ограничьте в промпте («не больше
2 предложений»). Telegram не пропускает сообщения длиннее 4096 символов, бот
аккуратно обрежет по границе, не ломая разметку.

**Хочу свой шаблон для одной ленты.** Есть в базе, команды пока нет:

```bash
cd /opt/rss-deepseek-bot
sqlite3 data/bot.db "UPDATE feeds SET template='Свой промпт для {title}: {summary}' WHERE id=2"
```

Такой шаблон перекрывает общий только для этой ленты. Установите `sqlite3`, если
нужно: `sudo apt install -y sqlite3`.

**Одна и та же новость опубликовалась дважды.** Не должно происходить: записи
различаются по `guid`, правки заголовка и метки в ссылке ключ не меняют. Если
всё же случилось — вероятно, лента выдаёт разные `guid` для одной новости;
напишите, разберём.

**Как начать с чистого листа.** Остановить сервис, удалить `data/bot.db`, запустить
снова: ленты, настройки и архив прочитанного сбросятся к исходным.
