# Настройка

Всё настраивается командами в личке с ботом — файлы после установки править не нужно.
Команды принимаются только от аккаунтов из `ADMIN_IDS`, остальным бот не отвечает.
Всё то же самое (кроме управления лентой процесса) доступно и в виде веб-панели —
см. раздел «Веб-панель управления» ниже, если печатать команды надоело.

Если бот ещё не установлен — сначала [INSTALL.md](INSTALL.md).

---

## Порядок первой настройки

Рекомендую именно такую последовательность: сначала посмотреть результат в личке
и только потом пускать в канал.

```
/debug on                          # посты будут приходить вам, не в канал
/add https://lenta.ru/rss/news     # первая лента
/checknow                          # получить пост в личку
/settemplate ...                   # поправить промпт, если результат не нравится
/checknow                          # та же новость по новому промпту
/debug off                         # публикуем в канал
```

Разбор каждого шага — ниже.

## Веб-панель управления

Альтернатива командам — те же ленты, шаблон/формат, настройки, VK/Claude,
список постов с перегенерацией через ИИ, но в браузере. Работает в том же
процессе бота, отдельного сервиса разворачивать не нужно.

**Включение**

```
WEB_PANEL_PASSWORD=длинный-случайный-пароль
WEB_PANEL_PORT=8090        # необязательно, по умолчанию 8090
```

в `.env`, затем перезапуск. Без пароля панель не поднимается вовсе — это
осознанный безопасный дефолт, а не то, что можно забыть включить по ошибке.
Заработавший адрес видно в журнале: `journalctl -u rss-deepseek-bot | grep панель`.

**Важно про безопасность.** Без `WEB_PANEL_PUBLIC_URL` панель слушает
`0.0.0.0:<порт>` — то есть открыта всему интернету, если на сервере нет
фаервола, обычным HTTP без шифрования: пароль при входе и всё содержимое
страниц идёт по сети в открытом виде. Для личного использования это
приемлемый компромисс, но не для панели, в которую заходят не только вы.
Более безопасные варианты:

* **SSH-туннель, без публичного порта вообще** — на сервере `WEB_PANEL_PORT=8090`,
  а на своей машине `ssh -L 8090:localhost:8090 root@сервер` и открыть
  `http://localhost:8090`. Порт наружу не торчит, шифрование даёт сам SSH.
* **Домен + HTTPS через nginx** — см. следующий раздел. Заодно это
  единственный способ открыть панель прямо в Telegram.

Сессия живёт неделю (кука, `HttpOnly`), защита от подбора пароля — 5 неудачных
попыток и 15 минут блокировки с одного адреса. Выход — кнопка «Выйти» в шапке.

**Чего в панели нет** — управления процессом бота (перезапуск/остановка
службы), это по-прежнему `systemctl` на сервере; и правки исходного текста
шаблонов при отсутствии текста — валидация та же, что и у команд
(`/setformat`, `/settemplate`).

### Открыть панель в Telegram (домен + HTTPS)

Telegram Web App (кнопка `/panel`, кнопка меню бота) открывает **только**
`https://` с настоящим сертификатом — самоподписанный не подойдёт, IP:порт
без домена тоже. Значит нужен домен (подойдёт любой поддомен, который
можно направить A-записью на IP сервера) и nginx с certbot перед ботом.

1. В DNS-панели домена добавьте A-запись: имя — например `panel` или
   `newsbot`, значение — IP сервера. Подождите, пока разойдётся (от
   нескольких минут до пары часов — можно проверить `dig +short ваш-домен`,
   должен вернуться IP сервера).
2. На сервере — свой nginx-сайт для этого домена, проксирующий на порт
   панели:
   ```nginx
   server {
       listen 80;
       server_name panel.example.com;
       location / {
           proxy_pass http://127.0.0.1:8090;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }
   }
   ```
   Сохранить в `/etc/nginx/sites-available/panel`, включить
   `ln -s /etc/nginx/sites-available/panel /etc/nginx/sites-enabled/`,
   проверить `nginx -t` и перечитать `systemctl reload nginx`.
3. Сертификат: `certbot --nginx -d panel.example.com` (или
   `--non-interactive --agree-tos -m ваш@email --redirect` для
   автоматического режима) — certbot сам допишет `listen 443 ssl` и
   редирект с 80 на 443 в конфиг из шага 2.

   Если на сервере 443 уже занят чем-то другим (например Docker-контейнером
   VPN — так и было на нашем сервере), certbot всё равно допишет `listen 443`
   и nginx откажется перечитывать конфиг («Address already in use»). Лечится
   вручную: в файле сайта из шага 2 (`/etc/nginx/sites-enabled/...`) заменить
   везде `443` на свободный порт, например `8443` — и в блоке `return 301
   https://$host...` тоже, там его certbot не подставляет автоматически.
   Панель тогда откроется на `https://panel.example.com:8443` — Telegram
   Web App непривычным портом не смущается, требование только к схеме
   `https` и доверенному сертификату.
4. В `.env` бота: `WEB_PANEL_PUBLIC_URL=https://panel.example.com` (свой
   порт, если пришлось его менять, — без слэша на конце), перезапуск. С
   этого момента бот сам:
   * переключает порт панели на `127.0.0.1` — снаружи виден только https
     через nginx, прямой http-доступ по IP:порту закрывается;
   * ставит кнопку меню «Панель» у каждого `ADMIN_IDS` (сработает, только
     если админ хоть раз писал боту — иначе Telegram не даёт поставить
     кнопку меню для незнакомого чата, тогда воспользуйтесь `/panel`
     вручную);
   * включает `/panel` — команда с кнопкой, открывающей панель как Mini
     App внутри Telegram (разворачивается на весь экран, учитывает вырезы
     экрана);
   * включает автовход без пароля для ADMIN_IDS — см. следующий раздел.

Если DNS ещё не разошёлся, `certbot` откажет с ошибкой вида «DNS problem:
NXDOMAIN» — это не поломка, просто рано, попробуйте ещё раз позже.

### Автовход из Telegram без пароля

Когда панель открыта Web App-кнопкой внутри Telegram (не просто ссылкой в
браузере), она сама, ещё до показа формы пароля, пробует войти по подписи
Telegram — `initData`, которую Telegram Web App передаёт странице и которую
подделать без BOT_TOKEN невозможно (тот же принцип, что у `verify` на
серверах самого Telegram). Если Telegram-аккаунт, из-под которого открыта
панель, есть в `ADMIN_IDS` — вход происходит мгновенно, без единого клика.
Если нет (или панель открыта просто в браузере, не из Telegram) — просто
остаётся обычная форма с паролем, ничего не ломается.

Работает всегда, как только настроен `WEB_PANEL_PUBLIC_URL` — отдельно
включать не нужно. Подделать вход за другого админа нельзя: подпись
проверяется криптографически на каждый запрос, а не полагается на то, что
сказал браузер.

## Ленты

```
/add https://lenta.ru/rss/news
/add https://habr.com/ru/rss/best/daily/ Хабр
```

Второе слово и всё после него — необязательное название, оно попадает в `{source}`
и в подпись поста. Если не указать, бот возьмёт название из самой ленты.

При добавлении адрес сразу проверяется: бот скачивает ленту, считает записи
и показывает последнюю. Если лента недоступна или пустая — она не добавится,
и вы увидите причину.

| Команда | Что делает |
|---|---|
| `/list` | все ленты: статус, время последней проверки, число прочитанных, ошибки |
| `/del 1` | удалить ленту вместе с её архивом прочитанного |
| `/pause 1` | временно выключить одну ленту |
| `/resume 1` | включить обратно |
| `/test 1` | прогнать последнюю новость через шаблон и показать результат, ничего не публикуя |

Номер (`id`) берётся из `/list`.

**Где брать адреса лент.** Обычно `https://сайт/rss`, `/feed`, `/rss.xml`,
`/feed.xml`. У многих сайтов ссылка есть в подвале страницы. Поддерживаются
и RSS, и Atom. Проверить вручную: `curl -s https://сайт/rss | head -20` — должен
быть XML с `<item>` или `<entry>`.

**Сколько лент.** Ограничения нет, но помните про расход модели: каждая новость —
один запрос. Оценить и проконтролировать поможет `/usage`.

## Шаблон для модели

Это главная настройка — именно она определяет, как будут выглядеть новости.
Промпт целиком ваш; бот только подставляет в него данные новости.

Посмотреть текущий:

```
/template
```

Задать свой — одним сообщением, перенос строки в Telegram это **Shift+Enter**:

```
/settemplate Ты редактор новостного канала. Перепиши новость на русском.

Требования:
- 2 предложения, только факты из источника
- никаких оценок и воды
- в конце 2 хештега

Заголовок: {title}
Текст: {summary}
```

Доступные плейсхолдеры:

| Плейсхолдер | Что подставляется |
|---|---|
| `{title}` | заголовок новости |
| `{summary}` | текст новости из ленты (HTML вычищен) |
| `{link}` | ссылка на источник |
| `{source}` | название ленты |
| `{published}` | дата публикации |

Хотя бы один из `{title}` / `{summary}` обязателен — без них модель не получит
саму новость, и такой шаблон бот не сохранит.

Вернуть исходный: `/reset template`.

### Свой промпт для одной ленты

Общий промпт — на все ленты сразу, но у конкретной ленты может быть
собственный (например: одна лента — сплошная жёлтая пресса, для неё нужен
более скептичный тон, а остальные ленты трогать не хочется). Работает
независимо от общего — что зададите для ленты, то и используется только
для неё, остальные продолжают жить на общем.

```
/feedtemplate 3               # что сейчас у ленты #3 — свой промпт или общий
/setfeedtemplate 3 Перепиши коротко и с подковыркой.

Заголовок: {title}
Текст: {summary}
/resetfeedtemplate 3          # убрать свой — вернуться на общий
```

id ленты — из `/list`; там же, если у ленты есть свой промпт, будет пометка
`📝 свой промпт`. То же самое в веб-панели — кнопка «🤖 Промпт» в списке
лент открывает страницу редактирования; пустое поле при сохранении означает
то же самое, что `/resetfeedtemplate` — вернуться к общему.

Плейсхолдеры и правило «хотя бы `{title}` или `{summary}`» — те же, что и у
общего промпта. `/regen` на посте из этой ленты тоже использует её
собственный промпт, если он задан.

### Примеры промптов

**Сухая выжимка:**

```
/settemplate Перепиши новость в одно предложение, максимально сухо, только факт.

{title}. {summary}
```

**С разбором и мнением:**

```
/settemplate Ты аналитик. Дай пересказ новости в 3 предложениях, затем строку
«Почему это важно:» и одно предложение о значимости. Без markdown.

Заголовок: {title}
Источник: {source}
Текст: {summary}
```

**Перевод на русский** (для англоязычных лент):

```
/settemplate Переведи новость на русский язык и сократи до 3 предложений.
Имена и названия компаний оставь в оригинале.

{title}
{summary}
```

После любой правки проверяйте `/test <id>` — увидите результат, ничего не публикуя.

## Формат поста

Шаблон отвечает за текст от модели, формат — за вёрстку готового сообщения.

```
/format
```

По умолчанию:

```
{ai}

<a href="{link}">Источник</a>
```

Пост начинается сразу с текста от модели: заголовок из ленты в него не
выводится (он на языке оригинала, а модель уже пересказала суть), название
ленты — тоже. Если они нужны, добавьте `{title}` и `{source}` в формат.

Здесь `{ai}` — ответ модели, остальные плейсхолдеры те же. Поддерживаются
[HTML-теги Telegram](https://core.telegram.org/bots/api#html-style):
`<b>`, `<i>`, `<u>`, `<s>`, `<code>`, `<pre>`, `<a href>`, `<blockquote>`.

Примеры:

```
/setformat {ai}

<a href="{link}">{source}</a>
```

```
/setformat <b>{title}</b>
<blockquote>{ai}</blockquote>
<a href="{link}">Источник</a> · {published}
```

Разметка проверяется при сохранении: незакрытый тег или тег, которого Telegram
не знает, бот отклонит с объяснением. Это не придирка — Telegram отверг бы такой
пост целиком, и публикация встала бы.

Вернуть исходный: `/reset format`.

### Картинки

Картинку бот берёт из самой новости и прикладывает к посту сам — плейсхолдера
для неё не нужно. Ищется она в таком порядке: `media:content` и
`media:thumbnail`, вложение `enclosure` с типом `image/*`, первый `<img>` в теле
записи. Счётчики и прозрачные пиксели отсеиваются, так что в пост попадает
иллюстрация, а не следящий гиф.

Если в ленте картинки нет вовсе — а такие ленты попадаются, — бот открывает
страницу новости и берёт `og:image`: ровно ту картинку, которую показывают
соцсети. Найденная картинка идёт и в Telegram, и в VK. Выключается отдельно:
`/set og_image 0`.

Чтобы это не превращалось в нагрузку, запрос к странице обставлен так:

* ходим только за теми новостями, которые уже отобраны к публикации, — не за
  всей выдачей ленты (это единицы запросов в час, а не сотни);
* читаем максимум 192 КБ и обрываем чтение на `</head>` — метатеги лежат там,
  и страница на 20 МБ обойдётся в один пакет;
* таймаут 12 секунд, без повторов;
* результат кладём в базу — включая «на странице картинки нет», иначе
  на каждую такую новость приходился бы лишний запрос при любой перепубликации;
* а вот неудачу (сайт ответил ошибкой или притормозил нас) не запоминаем:
  один случайный `429` иначе лишил бы ленту картинок навсегда.

В журнале это видно строками «картинка со страницы …» и «страница новости
не прочиталась …».

Как это выглядит, зависит от длины поста:

* до 1024 символов — фото с подписью, картинка крупная сверху;
* длиннее — обычное сообщение, картинка идёт превью над текстом (Telegram
  ограничивает подпись к фото 1024 символами, а резать пост ради картинки
  неправильно).

Если картинки в новости нет или Telegram её не принял, пост уходит обычным
текстом — публикация из-за этого не срывается.

Выключить целиком: `/set images 0`. Посмотреть, что получится на конкретной
ленте, — `/test <id>`: в предпросмотре написано, нашлась ли картинка.

## Редактирование опубликованных постов

Бот запоминает каждый настоящий пост в канале (не превью `/test`, не
отладочные посты в личку) — его можно найти и поправить прямо там, где он
уже опубликован, без ручного удаления и republish.

**Команды**

* `/posts [n]` — последние опубликованные посты (по умолчанию 10), с id,
  типом (текст/фото/альбом) и временем публикации.
* `/edit <id>` — карточка поста: текущий текст, ссылка на исходную новость,
  подсказка, что делать дальше. Ничего не меняет.
* `/setpost <id> <текст>` — заменить текст вручную. Проверяется разметка
  (как в `/setformat`) и что текст укладывается в лимит Telegram — 1024
  символа для поста с картинкой (подпись), 4096 для текстового.
* `/regen <id> [пожелание]` — перегенерировать текст через ИИ заново из
  той же исходной новости (заголовок/сводка/ссылка, какими они были при
  публикации — а не текущая версия страницы источника, если её успели
  поправить). Пожелание необязательно и добавляется к промпту как есть,
  например `/regen 42 покороче и без хештегов`. Использует активный сейчас
  бэкенд — обычный LLM или Claude, если включён `/claude on`, так что старый
  пост, опубликованный на DeepSeek, можно перегенерировать через Claude
  и наоборот.
* `/delimage <id> <номер>` — убрать одну картинку из уже опубликованного
  альбома (посты с несколькими картинками — см. «Несколько картинок в
  посте»). Номера картинок и подсказка — в `/edit <id>`. Первую картинку
  (с ней связан текст поста) убрать нельзя; остальные — можно, по одной.
  То же самое есть и в веб-панели, на странице поста.

**Что не редактируется**

Сама картинка(-и) — можно только убрать лишнюю из альбома (`/delimage`),
но не подменить на другую. Если хочется сменить картинку целиком, проще
удалить сообщение в Telegram и переопубликовать новость вручную.

**Если Telegram отказал в правке**

Самые частые причины: пост старше ~48 часов (у Telegram есть практический
предел на редактирование старых сообщений), бота разжаловали из админов
канала, или сообщение удалили руками. Бот сообщает причину в ответе на
`/setpost`/`/regen`, текст в базе при отказе не меняется — то, что видно в
`/edit <id>`, всегда совпадает с тем, что реально в канале.

## Дубли между лентами

Разные ленты об одной и той же новости хобби-индустрии пишут регулярно —
анонс производителя подхватывают сразу несколько сайтов, каждый своими
словами. Бот сравнивает заголовок и краткое содержание новой записи с
постами за последние несколько дней; если похоже — не публикует, а кладёт
в очередь на ручной разбор.

### Как это устроено

Сравнение — по общим словам заголовка и summary (индекс Жаккара) с постами
за `dedup_window_days` дней. Совпадением считается только когда **и**
заголовок, **и** summary похожи одновременно — иначе типовая фраза вроде
«Games Workshop анонсировала» сама по себе схлопывала бы никак не связанные
новости. Итоговая схожесть должна дотянуть до `dedup_threshold` процентов.

Найденный дубль **не публикуется и не теряется**: помечается прочитанным
(чтобы не проверять его каждый цикл заново) и уходит в очередь — админам
приходит уведомление, а в веб-панели появляется раздел «Дубли».

### Разбор очереди

В веб-панели, вкладка «Дубли» — список записей с картинкой-превью,
заголовком, источником, на какой уже опубликованный пост похоже и с каким
процентом. Открыв запись, можно:

* **Опубликовать всё же** — если совпадение ложное: новость реально
  новая, просто заголовок случайно похож. Публикация идёт тем же путём,
  что и обычная — через текущий промпт, формат и активный бэкенд ИИ.
* **Удалить** — подтвердить, что это действительно дубль; запись просто
  убирается из очереди.

То же самое коротко — командой `/duplicates` в Telegram (список и ссылка
на веб-панель для действий).

### Настройка

* `/set dedup_enabled 0` — выключить совсем (по умолчанию включено).
* `/set dedup_window_days 3` — за сколько последних дней сравнивать посты.
* `/set dedup_threshold 55` — порог схожести в процентах; выше — строже
  (меньше ложных срабатываний, но и часть настоящих дублей может
  проскочить в канал), ниже — наоборот.

Разобранные записи, которые провисели в очереди больше месяца, чистятся
автоматически при плановой уборке базы — если за это время админ ни разу
не заглянул в «Дубли», новость уже не актуальна.

## Публикация в VK

Бот умеет дублировать новости на стену сообщества VK. Telegram остаётся
основным адресатом: в VK пост уходит **после** удачной публикации в канале.
Так новость не задваивается в VK, если Telegram ответил ошибкой и публикация
пойдёт по новой на следующем проходе.

### Что нужно получить

1. **Ключ доступа сообщества.** В сообществе: «Управление» → «Работа с API» →
   «Создать ключ». Права — **Стена** и **Фотографии**. Нужен ключ именно
   сообщества, пользовательский здесь ни к чему: сообщество публикует само у себя.
2. **Числовой id сообщества** — не короткое имя. «Ещё» → «Статистика», id будет
   в адресе страницы, либо через <https://regvk.com/id/>.

### Настройка

В `.env`:

```
VK_TOKEN=vk1.a....
VK_GROUP_ID=123456789
```

После перезапуска проверьте ключ, ничего не публикуя:

```
/vk check
```

Ответ с названием сообщества значит, что доступ есть. Ошибка чаще всего означает
отозванный ключ или нехватку прав «Стена» / «Фотографии».

### Команды

| | |
|---|---|
| `/vk` | состояние и краткая инструкция |
| `/vk on` · `/vk off` | включить и выключить дублирование |
| `/vk group <id>` | сменить сообщество без правки `.env` |
| `/vk check` | проверить ключ запросом к VK, без публикации |
| `/vk test <id ленты>` | опубликовать последнюю новость ленты в VK по-настоящему |

`/vk test` делает **настоящую** запись на стене — если она не нужна, удалите её
вручную. Для безопасного просмотра есть `/test <id>`: он показывает и пост для
Telegram, и текст, который уйдёт в VK, ничего никуда не отправляя.

### Чем пост в VK отличается от телеграмного

Текст тот же, но VK не понимает HTML, поэтому:

* теги убираются — жирный заголовок станет обычной строкой;
* ссылки разворачиваются в текст: `<a href="URL">Источник</a>`
  превращается в `Источник: URL`, чтобы адрес не потерялся.

### Картинка в VK

Картинка из новости уходит настоящим фото, и ничего сверх `VK_TOKEN`
с `VK_GROUP_ID` для этого не нужно.

Здесь у VK жёсткое ограничение: **загружать фото на стену разрешено только
пользовательскому ключу.** Ключу сообщества и `photos.getWallUploadServer`,
и `photos.getUploadServer` отвечают ошибкой 27 «method is unavailable with
group auth» — права ключа тут ни при чём.

Без `VK_USER_TOKEN` бот прикрепляет к записи ссылку на новость: VK собирает
карточку и сам берёт картинку из `og:image` страницы. Если и карточку он
собрать не смог (`link_photo_sizing_rule`), запись уходит голым текстом —
новость важнее оформления.

### Проверенный тупик

Ключом сообщества фото всё же можно загрузить — через
`photos.getMessagesUploadServer`, и `wall.post` такое вложение **принимает без
ошибки**. Но в опубликованной записи оно **не отображается**. Приёмка вложения
через API не означает, что оно видно читателю; повторять этот путь не стоит.

### Как получить пользовательский ключ без своего приложения

Создание standalone-приложения VK сейчас требует юрлица, но собственное
приложение и не нужно — подойдёт id любого существующего:

1. Откройте в браузере под аккаунтом **администратора сообщества**:

   ```
   https://oauth.vk.com/authorize?client_id=6121396&scope=photos,wall,groups,offline&response_type=token&redirect_uri=https://oauth.vk.com/blank.html&display=page
   ```

   `6121396` — id приложения «VK Admin». Подойдёт и `2685278` (Kate Mobile).

2. Разрешите доступ — откроется пустая страница.
3. Из адресной строки скопируйте всё между `access_token=` и `&expires_in`.
4. Впишите в `.env` строкой `VK_USER_TOKEN=vk1.a....` и перезапустите бота.

Со `scope=offline` ключ бессрочный, хранить его надо как пароль. Публикует
по-прежнему сообщество: пользовательский ключ идёт только на загрузку фото.
Заодно он открывает `wall.delete` и `wall.getById` — то есть бот сможет
убирать за собой проверочные записи.

Проверить, что всё на месте: `/vk check` — делает тот же запрос, что и
публикация фото, но без самой загрузки и без записи на стене.

### Если пост не появился

Смотрите журнал: `journalctl -u rss-deepseek-bot -f`. Ошибки VK пишутся строкой
`VK: пост не опубликован — ...`.

* `ошибка 5` — ключ недействителен или отозван, создайте заново;
* `ошибка 214` — у ключа нет права «Стена» либо сообщество запрещает публикацию;
* `флуд-контроль` — VK отклонил повтор: такой же текст уже публиковался;
* `недоступен ключу сообщества` — так VK отвечает на загрузку фото; это
  не поломка, а причина, по которой нужен `VK_USER_TOKEN` (см. выше).

Отключить дублирование, не трогая `.env`: `/vk off`.

## Режим Claude

Платная обработка через Claude (Anthropic Messages API) вместо DeepSeek/LLM_*
из `.env` — включается и выключается на ходу, без перезапуска, командой
`/claude on` · `/claude off`.

### Что нужно

1. Ключ на [console.anthropic.com/settings/keys](https://console.anthropic.com/settings/keys).
2. В `.env`: `CLAUDE_API_KEY=sk-ant-...`, при желании `CLAUDE_MODEL=` (по
   умолчанию `claude-sonnet-5`), затем перезапуск бота — ключ читается
   только при старте, а вот включение режима им уже не требует.
3. `/claude on`

### Команды

/claude — состояние и эта справка
/claude on · /claude off — включить и выключить режим
/claude check — проверить ключ живым запросом, ничего не публикует
/claude test &lt;id ленты&gt; — прогнать последнюю новость ленты через Claude,
показать в личке (аналог /test, но принудительно через Claude независимо от
текущего состояния /claude on|off)

Промпт и формат поста общие с обычным режимом (`/template`, `/format`) —
отдельного шаблона под Claude нет.

### Деньги

`/usage` считает расход только для DeepSeek/LLM_* — у Claude свой отдельный
счёт и лимиты на console.anthropic.com, бот их не отслеживает и не
предупреждает о расходе.

## Режим Gemini

То же самое, что режим Claude выше по механике (свой ключ, включается и
выключается на ходу, без перезапуска), но проще и обычно **бесплатно** —
у Gemini свой бесплатный тариф. Разница с Claude — картинки: в режиме
Gemini они как в обычном режиме, одна, а не альбом.

Claude и Gemini не могут быть включены одновременно — это один и тот же
рубильник «через что обрабатывать вместо LLM_*», включение одного гасит
другой (и командой, и в веб-панели).

### Что нужно

1. Ключ на [aistudio.google.com/apikey](https://aistudio.google.com/apikey).
2. В `.env`: `GEMINI_API_KEY=...`, при желании `GEMINI_MODEL=` (по
   умолчанию `gemini-3.6-flash` — если Google переименует модели, впишите
   актуальное имя), затем перезапуск бота.
3. `/gemini on`

### Команды

/gemini — состояние и эта справка
/gemini on · /gemini off — включить и выключить режим
/gemini check — проверить ключ живым запросом, ничего не публикует
/gemini test &lt;id ленты&gt; — прогнать последнюю новость ленты через Gemini,
показать в личке

Промпт и формат поста общие с обычным режимом (`/template`, `/format`).
`/usage` на Gemini не распространяется — свои лимиты смотрите в Google AI
Studio.

### Почему не через LLM_BASE_URL напрямую

Можно было бы вместо отдельного режима просто прописать `LLM_BASE_URL`/
`LLM_MODEL`/`LLM_API_KEY` под Gemini (у него OpenAI-совместимый API,
технически заработало бы) — но тогда DeepSeek/OpenRouter конфигурация
терялась бы, и вернуться одной командой было бы нельзя. Отдельный режим
даёт переключаться туда-обратно, не теряя настройки ни одного из провайдеров.

## Несколько картинок в посте

По умолчанию к посту прикладывается одна картинка (из ленты или og:image
страницы). Включив `/multiimages on`, бот вместо одной открывает
страницу новости целиком и качает **несколько** картинок из статьи —
og:image-подобные метатеги в приоритете, затем `<img>` из тела статьи, до
`/set max_images N` штук (1-10, по умолчанию 6). Картинки уходят в канал
альбомом; если после фильтрации осталась ровно одна — обычным фото с
подписью, как без этого режима. Вернуть как было — `/multiimages off`.

Работает при любом активном бэкенде текста — обычном, Claude, Gemini —
это отдельный переключатель, а не побочный эффект `/claude on`.

Дороже обычного режима по трафику и времени (страница + до 10 картинок),
поэтому выключено по умолчанию. Скачивание идёт пачками по 4 картинки
параллельно, а не по одной — на 6-10 картинок это в несколько раз быстрее,
чем строго последовательно.

### Если картинок в посте меньше, чем ожидали

Каждая картинка скачивается отдельно и при неудаче просто пропускается
(сайт не ответил, оказалось не картинкой, больше 10 МБ — это и телеграмный
лимит на фото тоже) — бот запрашивает с запасом сверх `max_images`, чтобы
несколько неудач не оставили пост с картинками меньше настроенного. Как и
в обычном режиме, отсутствие иллюстрации не повод терять новость.
Подробности в журнале: `картинка не скачалась, пропускаю: ...`.

## Режим отладки

Чтобы настраивать шаблон, не засоряя канал:

```
/debug on
/checknow
```

Пост приходит вам в личку с пометкой «ОТЛАДКА» и выглядит ровно так, как выглядел
бы в канале. Правите `/settemplate` или `/setformat`, снова `/checknow` — и видите
**ту же самую новость**, обработанную по-новому. Так можно сравнивать варианты
промпта на одном материале.

Важные свойства режима:

* в канал не уходит ничего;
* новости не помечаются прочитанными — после `/debug off` они опубликуются как
  обычно, ничего не теряется;
* автоматический цикл в отладке молчит, иначе одни и те же посты приходили бы
  в личку каждые `interval` минут. Проверка только по `/checknow`;
* кэширование лент отключено, поэтому одну новость можно прогонять сколько нужно.

Если бот на паузе (`/stop`), отладка тоже ничего не покажет — сначала `/start`.

Разовый предпросмотр без включения режима — `/test <id>`.

## Канал и публикация

| Команда | Что делает |
|---|---|
| `/setchannel @my_channel` | сменить канал; бот сразу проверит, что видит его |
| `/stop` | пауза: ленты не проверяются, публикаций нет |
| `/start` | снять паузу |
| `/checknow` | проверить ленты немедленно, не дожидаясь интервала |
| `/status` | полное состояние: канал, модель, ленты, все параметры |

Бот должен быть администратором канала с правом «Публикация сообщений». Если права
нет, в логах появится `Forbidden`, а новости останутся непрочитанными и уйдут
в канал после того, как права дадите — ничего не потеряется.

## Модель и деньги

По умолчанию используется OpenRouter и модель `deepseek/deepseek-v4-flash`.

```
/model                                     # текущая модель и подсказки
/setmodel deepseek/deepseek-v3.2           # сменить
```

Новая модель сразу проверяется живым запросом. Если она не отвечает или слага
не существует, бот вернёт прежнюю — публикации не сломаются.

**Бесплатных версий DeepSeek на OpenRouter нет.** Платные стоят копейки — оценка
при ~1500 токенах промпта и ~250 ответа на новость:

| Модель | За 1000 новостей |
|---|---|
| `deepseek/deepseek-v4-flash` (по умолчанию) | ~22 ₽ |
| `deepseek/deepseek-v3.2` | ~40 ₽ |
| `deepseek/deepseek-chat` | ~52 ₽ |
| `deepseek/deepseek-v4-pro` | ~70 ₽ |

При 20 новостях в день на модели по умолчанию выходит около 13 ₽ в месяц.

Если нужен строго нулевой счёт — бесплатные модели есть, но не DeepSeek:

```
/setmodel google/gemma-4-31b-it:free
/setmodel nvidia/nemotron-3-super-120b-a12b:free
/setmodel openai/gpt-oss-20b:free
```

У них суточный лимит запросов и очереди при перегрузке. Актуальный список —
[openrouter.ai/models?max_price=0](https://openrouter.ai/models?max_price=0).

Сменить провайдера целиком (например, на DeepSeek напрямую) можно в `.env`:
`LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`. Подойдёт любой OpenAI-совместимый API.

## Лимиты ИИ и предупреждения

Бот считает свои запросы по суткам UTC и предупреждает в личку, когда израсходовано
70% и 90% лимита:

```
🟡 Израсходовано 70% суточного лимита запросов
Запросов сегодня: 35 из 50
Модель: google/gemma-4-31b-it:free
Лимит: бесплатный тариф OpenRouter
Обнулится через 9 ч 12 мин (00:00 UTC)
```

Повторно на том же пороге за те же сутки сообщение не приходит. Пороги меняются:

```
/set alert_thresholds 50,80,95      # свои пороги
/set alert_thresholds               # пусто — выключить предупреждения
```

Текущая картина в любой момент:

```
/usage
```

Отслеживаются две разные вещи:

* **Запросы в сутки.** Актуально для бесплатных моделей (`:free`): у них лимит
  50 запросов в сутки, если кредиты никогда не покупались, и 1000, если куплено
  10 и более. Какой применить, бот определяет сам по данным ключа. Если нужно
  задать вручную: `/set free_daily_limit 50`.
* **Кредиты.** Если на ключе OpenRouter выставлен лимит трат, бот следит
  за остатком и предупреждает на тех же порогах.

Счётчик запросов бот ведёт свой, потому что провайдер его не отдаёт. Если тем же
ключом пользуется что-то ещё, эти запросы бот не увидит.

**Когда лимит всё же исчерпан**, модель отвечает ошибкой 429. Что произойдёт,
зависит от настройки `on_llm_error`:

* `skip` (по умолчанию) — новость откладывается: не публикуется и **не**
  помечается прочитанной, поэтому уйдёт в канал со следующей попыткой, уже
  обработанной. Админам приходит предупреждение в личку — не чаще раза в час,
  чтобы затянувшийся сбой не превратился в поток сообщений;
* `raw` — новость публикуется без обработки, с исходным текстом из ленты.
  Ничего не задерживается, но пост будет «сырым», в том числе непереведённым.

```
/set on_llm_error raw
```

### Проверка, что новость действительно обработана

Мало получить ответ модели — он должен быть переведён. Модель иногда
возвращает исходник как есть или отвечает пустотой, и такой пост ничем не лучше
необработанного. Поэтому:

* **пустой ответ повторяется.** Раньше он сразу считался отказом; теперь запрос
  идёт заново, а если модель оборвалась по лимиту токенов (`finish_reason=length`)
  — на повтор ей даётся вдвое больший бюджет;
* **ответ проверяется на русский язык** (`require_russian`, по умолчанию
  включено). Считается доля кириллицы среди букв: меньше трети — значит, перевода
  не было. Названия и хештеги латиницей порог не ломают, короткие ответы
  не проверяются;
* если текст не на русском, модель переспрашивают ещё раз с прямым указанием
  «ответ должен быть на русском, не копируй исходный текст». Только после
  второй неудачи новость откладывается по правилу `on_llm_error`.

Выключить языковую проверку (например, для англоязычного канала):

```
/set require_russian 0
```

## Все параметры

Смотреть текущие значения — `/status`. Менять — `/set <ключ> <значение>`.

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `interval` | 15 | минут между проверками лент (`/interval 30`) |
| `max_per_cycle` | 3 | максимум новостей из одной ленты за проход — защита от лавины |
| `post_delay` | 5 | пауза между публикациями, секунды |
| `backfill` | 1 | сколько новостей опубликовать при первом опросе новой ленты; остальная история помечается прочитанной |
| `on_llm_error` | skip | `skip` — отложить до следующей попытки, `raw` — публиковать без обработки |
| `require_russian` | 1 | `0` — не проверять, что модель перевела новость на русский |
| `disable_preview` | 0 | `1` — отключить превью ссылок в постах |
| `images` | 1 | `0` — не прикладывать картинку из новости |
| `og_image` | 1 | `0` — не дочитывать картинку со страницы, если её нет в ленте |
| `multi_images` | 0 | `1` — несколько картинок альбомом вместо одной, при любом режиме (см. «Несколько картинок в посте») |
| `max_images` | 6 | сколько картинок скачивать за раз при `multi_images` (1-10) |
| `vk_enabled` | 1 | дублировать ли в VK; работает только с `VK_TOKEN` (`/vk on`, `/vk off`) |
| `vk_group_id` | — | id сообщества VK, если нужно переопределить `.env` (`/vk group`) |
| `claude_mode` | 0 | обработка через платный Claude вместо LLM_*; управляется `/claude on`, `/claude off` |
| `keep_seen` | 500 | сколько отметок «прочитано» хранить на ленту |
| `alert_thresholds` | 70,90 | пороги предупреждений о расходе, в процентах |
| `free_daily_limit` | 0 | суточный лимит запросов; 0 — определять автоматически |
| `dedup_enabled` | 1 | `0` — не искать дубли между лентами (см. «Дубли между лентами») |
| `dedup_window_days` | 3 | за сколько последних дней сравнивать посты на схожесть |
| `dedup_threshold` | 55 | порог схожести в процентах, после которого считаем дублем |

## Сколько бот ест на сервере

Коротко: около **170 МБ памяти**, несколько мегабайт диска, доли процента CPU.
Со временем не растёт.

**Память.** Почти вся она уходит на импорт библиотек, а не на работу: один
только `aiogram` тянет ~150 МБ (это сотни моделей pydantic), `aiohttp` — ещё
~29 МБ. Сам цикл опроса добавляет ~5 МБ и дальше держится на месте: пять
проходов подряд по трём лентам (277 записей) дали 171.9 → 173.0 МБ и плато.
Утечки нет, перезапускать «для профилактики» не нужно.

Чтобы освободившаяся после разбора лент память возвращалась системе, а не
оставалась за процессом, после каждого прохода вызывается `malloc_trim`
(`release_memory` в `publisher.py`) — на практике это отдаёт 15–20 МБ.
Разбор лент идёт в пуле из двух потоков: у каждого потока своя арена malloc,
и пул по умолчанию (до 32 потоков) впустую держал бы десятки мегабайт.

**Диск.** База растёт только отметками «прочитано»: не больше `keep_seen`
(по умолчанию 500) на ленту. Пять лент — это максимум 2500 строк, единицы
сотен килобайт. Таблица расхода — одна строка в сутки, хранится 60 дней.
Раз в 6 часов бот подчищает обе таблицы и ужимает WAL (`Storage.maintain`),
результат пишется в журнал строкой «уборка в базе».

**Ограничения systemd.** В юните заданы `MemoryHigh=256M` и `MemoryMax=384M`:
если бот однажды всё-таки потечёт, его убьёт и перезапустит, а не утащит за
собой сервер. Плюс `TasksMax=64` и ограничение частоты записи в журнал.

Посмотреть текущий расход:

```bash
systemctl status rss-deepseek-bot
systemctl show rss-deepseek-bot -p MemoryCurrent -p MemoryPeak
```

Отдельно стоит следить за системным журналом — он общий для всего сервера и
по умолчанию занимает до 10% диска:

```bash
journalctl --disk-usage
sudo journalctl --vacuum-size=200M     # ужать, если разросся
```

### Как подобрать интервал и лимиты

Расход = число новостей во всех лентах. Ленты проверяются каждые `interval` минут,
но за один проход из каждой берётся не больше `max_per_cycle`.

* **Спокойный канал, минимум денег:** `/interval 60` и `/set max_per_cycle 2`.
* **Оперативные новости:** `/interval 5`. Помните про лимит 20 запросов в минуту
  у бесплатных моделей — при `post_delay` в 5 секунд вы в него не упрётесь.
* **Много лент (10+):** держите `max_per_cycle` на 1–2, иначе первый проход
  после простоя выдаст в канал десятки постов подряд.

## Частые вопросы

**Бот молчит на команды.** Ваш id не в `ADMIN_IDS`. Проверьте `.env`, узнайте id
у [@userinfobot](https://t.me/userinfobot), перезапустите сервис. Посторонним бот
не отвечает намеренно.

**В канал ничего не публикуется.** По порядку: `/status` — не на паузе ли и не
включена ли отладка; есть ли активные ленты в `/list`; нет ли там ошибок;
`/checknow` — что ответит; `journalctl -u rss-deepseek-bot -n 50`.

**При добавлении ленты сразу прилетела одна новость.** Так и задумано: `backfill=1`.
Остальная история помечается прочитанной, чтобы канал не завалило. Отключить —
`/set backfill 0`.

**Новости приходят с большой задержкой.** Проверка идёт раз в `interval` минут,
плюс сам сайт может обновлять ленту с задержкой. Уменьшите `/interval`.

**Посты слишком длинные или обрезаются.** Ограничьте в промпте («не больше
2 предложений»). Telegram не пропускает сообщения длиннее 4096 символов, бот
аккуратно обрежет по границе, не ломая разметку.

**Хочу свой шаблон для одной ленты.** Есть в базе, команды пока нет:

```bash
cd /opt/rss-deepseek-bot
sqlite3 data/bot.db "UPDATE feeds SET template='Свой промпт для {title}: {summary}' WHERE id=2"
```

Такой шаблон перекрывает общий только для этой ленты. Установите `sqlite3`, если
нужно: `sudo apt install -y sqlite3`.

**Одна и та же новость опубликовалась дважды.** Не должно происходить: записи
различаются по `guid`, правки заголовка и метки в ссылке ключ не меняют. Если
всё же случилось — вероятно, лента выдаёт разные `guid` для одной новости;
напишите, разберём.

**Как начать с чистого листа.** Остановить сервис, удалить `data/bot.db`, запустить
снова: ленты, настройки и архив прочитанного сбросятся к исходным.
